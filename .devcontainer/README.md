# APIS Devcontainer Quickstart

1. Copy `.devcontainer/devcontainer.env.example` to `.devcontainer/devcontainer.env` and set the timezone if needed.
1. Build and run the devcontainer using your toolchain or IDE of choice.
1. Update `fm_eventmanager/settings.py` accordingly with payment processor secrets and the URL for the MQTT broker.
1. From within the devcontainer, run `uv run ./manage.py runserver` to start Django.

Visual Studio Code will automatically handle forwarding the needed ports to access services provided by the containers. For other toolchains or IDEs that do not automatically forward container ports, refer to the port listing in `devcontainer.json` for which ports to forward and refer to your IDE or toolchain's documentation for how to forward them. Either way, the host-side port for `nginx:80` will be needed to fill in the URL for the `MQTT_EXTERNAL_BROKER` variable in `settings.py` in step 3.

## Containers

This devcontainer setup contains a small orchestration of supporting containers in addition to the main container itself.

### Application (app)

This is built from `.devcontainer/Dockerfile` and provides a Debian-based Python 3.14 environment. Additional features are added to add Node.js for frontend compilation and uv for Python environment and dependency management.

When the devcontainer is run, it will automatically download frontend dependencies, build the frontend, download Python dependencies, create `fm_eventmanager/settings.py` from a boilerplate, and build the database. The boilerplate is already configured to connect to the database container, webmail container, and the MQTT broker, but you will need to edit the settings file to give it any payment processor API secrets and set the port in the `MQTT_EXTERNAL_BROKER` setting so the onsite frontend admin interface can connect to the MQTT broker's websocket endpoint.

### Postgres Database (db)

This container is running PostgreSQL 18.4. That's all there really is to say on the matter.

### Mail Catcher (mail)

This container is running smtp4dev, an SMTP mail catcher with a webmail interface. This is used to check and make sure that the emails generated by the system look good, have the correct information, and are being dispatched when they should be.

### Reverse proxy (nginx) and MQTT Broker (mosquitto)

The `mosquitto` container is built from `.devcontainer/mqtt/Dockerfile.mqtt` and provides an instance of Mosquitto 2.0.22 with the JWT authentication plugin compiled and deployed. The `nginx` container is used as a reverse proxy to properly upgrade Websocket requests to the websocket endpoint provided by Mosquitto.

## Known supported configurations

* Windows host using Docker Desktop and Visual Studio Code
* Linux host using Docker and Visual Studio Code
* Linux host using Docker, [Devsy](https://devsy.sh), and Codium
